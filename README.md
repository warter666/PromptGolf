# PromptGolf

用 prompt 引导模型完成任务的评测场：考生（人或模型）只能靠 prompt 引导一个模型写代码，环境量化"引导质量"——不只是测试通不通过，还包括模型从题面的哪些"缝隙"里掉了出去。

```
golf init password-validator          # 开一局
golf round "你的 prompt"              # 每引导一轮记录一次（快照+评测+反馈）
golf status --reveal                  # 练习模式看缝隙明细
golf report                           # 生成 HTML 可视化报告（缝隙地图）
golf auto order-total --rounds 5      # 自动模式：LLM 只靠公开测试反馈迭代
```

## 量化模型

一次"引导"被拆成三条可测的轴，缝隙不再是比喻而是数据点：

| 轴 | 缝的含义 | 测量手段 |
|---|---|---|
| spec 的缝 | 题面没说清，模型做了未声明的假设 | 缝隙探针（canary）：每条留白一个专属测试 |
| 世界的缝 | 环境本身有坑（过时文档、坏数据） | 环境陷阱：文档与数据不一致，模型是否审计 |
| 模型主动找缝 | 特判测试值、偷读私有测试、改资产 | 三层反作弊（静态 AST / 运行时守卫 / 完整性） |

```
得分 = (0.6 × 隐藏通过率 + 0.4 × 缝隙堵住率) × max(0, 1 − 0.5 × 作弊数) − 0.1 × (轮数 − 1)
```

关键设计：**考生手里的反馈只有公开测试**（故意不完整），隐藏测试与缝隙探针只用于评分。所以"缝隙地图 6 格里红了 3 格"回答的是总分回答不了的问题——模型错在哪种类型的留白上，以及考生第几轮把它堵住了。

## 缝隙地图

报告的 centerpiece。每格一条缝隙：

- 绿「一直稳」：从第一轮就没掉出去
- 蓝「第 k 轮堵住」：中途掉出去又爬回来（地图上能看出考生第几轮发现问题）
- 红「仍敞开」：到最后都没堵上

每格可展开：留白点是什么、出题人认定的合理解释、逐轮通过历史、最近一次失败的测试输出。

## 两个任务的两种缝

| 任务 | 缝型 | 例子 |
|---|---|---|
| 密码强度校验器 | spec 留白 ×6 | None/空输入、全角字符算不算字母数字、AaA 算不算"连续相同"、8 到 20 含不含端点、成功时返回什么 |
| 跨货币金额换算 | 环境陷阱 ×5 | rates.py 文档说汇率是"1 外币兑人民币"，但 EUR 的数据按"1 人民币兑 EUR"存——照文档公式写，公开测试全过，G01/G02 照样红 |

第二个任务的设计意图：文档与数据的矛盾**可以靠常识审计出来**（1 欧元不如 1 日元值钱是荒谬的；EUR/USD≈1.08 配 USD=7.2 可推出 1 EUR≈7.8 CNY），所以掉缝的模型不是运气差，是没核对世界。

## 决策与依据

零件都是教科书内容（pytest + junitxml、argparse、f-string 拼 HTML）。真正值钱的是这些取舍：

1. **评分主体是"缝隙堵住率"而不只是测试通过率。** 依据：面试考察的是引导过程，测试只能看终点；缝隙地图把"哪里没说清"变成可点开的数据点。反面：为了公平，每条缝的"认定解释"必须是可辩护的默认值（如"相同=字面相等"），出题随意的缝会在报告里显得像刁难——所以 task.json 里每条缝都写了 hint 和 intent 两行，解释权在报告里透明公开。

2. **私有测试在评测时才拷贝到暂存目录，配运行时守卫。** 依据：运行目录里根本不存在隐藏测试，考生改不了也搜不到；守卫用调用栈过滤——只有穿过被测入口文件的文件访问才记为作弊，pytest 自己读测试文件、写 pyc 缓存不算（第一版守卫没过滤，一次误报 19 条）。局限也如实说：守卫抓不到对 sys.modules 的内省，静态扫描抓不到语义等价的改写——反作弊抬高了作弊成本，不是理论上不可突破。

3. **手动模式优先：评测器不绑定任何模型。** 考生用顺手的任意 agent 改代码，`golf round` 只负责快照+评分。依据：面试考的是"人与模型的配合"，绑定哪家的 API 都会变成测模型；顺带让评测器零 API 依赖。auto 模式（OpenAI 兼容接口，纯 stdlib）只是演示驱动，让整条流水线一条命令跑通。

4. **可视化是单文件 HTML，纯手写 SVG/CSS，不引第三方库。** 依据：报告要能直接发给面试官，双击就开、断网可用；本机也没有 matplotlib。反面教训：junitxml 解析里 `find("failure") or find("error")` 把无子元素的 Element 当 falsy，失败全被吞成通过——第一版 demo 里"缝隙 6/6 已堵"的假满分就是这么来的，改成显式判空后 demo 数字才和手算对上。

5. **轮数计入惩罚（每多一轮 −0.1）。** 依据：prompt 效率是"引导质量"的一半——同样满分，两轮和八轮不是一回事。反面：上限 8 轮是硬截断，考生长考型策略会被误伤，参数在 task.json 的 scoring 里可调。

## 目录

```
golf/            core(任务/状态/评分) · evaluate(三套测试) · anticheat(三层)
                 report(HTML) · auto(LLM 驱动) · cli · fmt
tasks/
  password_validator/   task.json(缝隙定义) · prompt.md(故意留白的题面)
                        starter/ · public/ · hidden/ · canaries/
  order_total/          同上，rates.py 是文档陷阱本体
runs/            每局一个目录：run.json(逐轮记录) · history/ · .eval/ · report.html
```

出题方式：仿照现有任务写 task.json（gaps 数组：id/title/hint/intent）+ 题面 + 三套测试。约定：缝隙探针函数名必须以 `test_<G编号>_` 开头，公开测试放 public/（考生可见可跑），隐藏与探针分别放 hidden/ 与 canaries/（只在评测时进暂存目录）。
